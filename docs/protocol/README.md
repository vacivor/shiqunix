# IQUNIX A80 协议

这里整理 ShiQunix 使用的 A80 配置协议，以及决定键位行为的固件路径。当前实现依据有线 A80 的官方驱动抓包、网页实机验证和所提供固件的静态分析，更新至 2026-09-15。

## 阅读顺序

| 文档 | 内容 |
| --- | --- |
| [传输与事务](transport.md) | WebHID 接口、63 字节报告、校验、命令、读写顺序及异常处理 |
| [键位与动作](keymap.md) | 91 槽键位表、普通键和修饰键、媒体/系统/灯光动作、配置格式 |
| [背光](lighting.md) | 八种模式、亮度/速度/颜色、自定义 LED 数据与核对方式 |
| [Mac 模式](mac-mode.md) | 模式读取、四个物理位置覆盖、兼容编码及实测边界 |
| [Fn 与固件范围](fn.md) | 固定 Fn 表、已识别功能、写入口和未解决的问题 |

命令号、usage、动作字节与内存地址用十六进制表示；长度和槽位编号为十进制，偏移从零开始。文中 `data` 是去掉 Report ID 后的 WebHID 数据；`wire` 是包含 Report ID 的完整 USB 报告。

## 证据与适用范围

- **报文确认**：能够从捕获的请求/应答复现协议字节。回显本身不等于物理功能生效。
- **实机确认**：用户在当前 A80、有线连接及 Windows 主机上确认实际输出或灯效。Mac 模式指键盘的设备模式，不代表主机为 macOS。
- **静态分析**：来自指定固件镜像中的指令、常量和 HID 描述符，不能据此证明所有固件版本或主机都一样。
- **软件回归**：纯编码、样本回放和模拟设备测试，不替代硬件测试。

当前适配设备为 `05AC:024F`。L80 只提供外观预览，尚未验证其配置通信；无线与 macOS 主机的兼容映射行为也没有完整验证。

分析镜像标识：

| 镜像 | 标识 |
| --- | --- |
| Nordic nRF52832 | 74,300 字节，加载基址 `0x19000`；SHA-256 `bdb7b5a6013b1f969b541d51c32630442ba4c8f676cf0a3e5a269bd66d1a0a03` |
| SN32，更新器资源 4000 | SHA-256 `7a0a1f906797c65c3061360b9b848dfd59bdbbb3f20896819a8c7fcb98b79054` |

这些哈希标识分析输入，尚未用当前设备固件的完整回读确认版本相同。仓库收录协议说明、提取后的键表和回归所需报文样本，不包含原始驱动安装包、固件镜像或完整 USB 总线抓包。

## 实现与复核

- [protocol.mjs](../../src/protocol.mjs)：编码、应答解释和分片重组。
- [transport.mjs](../../src/transport.mjs)：串行事务、写前备份、写后核对。
- [profiles.mjs](../../src/profiles.mjs)：配置校验、当前表与导出表示转换。
- [回归样本](../../tools/fixtures/)：测试使用的报文与数据。
- [参考键表](../../src/data/captured-keymap.json)、[物理布局槽位](../../src/data/layout-candidates.json)、[固定 Fn 表](../../src/data/fn-reference.json)：机器可读数据。

在仓库根目录运行：

```sh
npm ci
npm run test:research
npm run lint
npm run build
```

研究测试只使用仓库内文件和模拟设备，不连接 USB。新增编码时，应分别记录字节来源、软件回归与物理验证结果，避免将“保存并读回一致”当成“目标功能已确认”。
