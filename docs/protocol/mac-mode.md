# Mac 模式与键位映射

本文说明键盘 Mac 模式下的修饰键覆盖、ShiQunix 使用的兼容编码，以及维护这些功能时需要保留的约束。当前实现针对已验证的 A80 协议；页面可切换 A80/L80 外观，不代表两个型号的 Mac 映射均已实测。

以下编码、命令和固件地址使用十六进制；物理槽位编号使用十进制，从 0 开始。键位表共 273 字节，每槽 3 字节，槽位 `n` 位于字节偏移 `3 × n`。

## 设备模式与主机键名

设备模式通过命令 `05`、偏移 `2C`、长度 `01` 读取，返回 payload 的第一个字节为模式值：

| 返回值 | 设备模式 |
| --- | --- |
| `00` | Windows |
| `01` | Mac |
| 其他值或读取失败 | 未识别，不能推定为 Windows 或 Mac |

实机切换 Windows → Mac → Windows 时，已读到 `00 → 01 → 00`。实现见 [transport.mjs](../../src/transport.mjs) 的 `readOsModeBlock()`。应用只读取此状态，没有通过键名显示选项修改设备模式。

设备仍使用同一张真实键位表。Mac 模式改变部分物理键的执行逻辑，并不是新增一张可编辑的 Fn 或 Mac 层。主机运行 Windows 还是 macOS，与键盘当前使用哪种模式是两个独立维度。

「键名显示：自动 / Windows / macOS」只控制本地文字：Windows 显示 Win/Alt，macOS 显示 Cmd/Opt。自动模式参考浏览器提供的主机平台，识别不到时使用 Windows 键名。该偏好不修改映射字节、不切换设备模式，也不能作为 macOS 主机兼容性已验证的证据。实现见 [key-display.mjs](../../src/key-display.mjs)。

## 原始 20 / B0 动作的位置覆盖

普通键动作格式为 `20 modifier-mask usage`。修饰位从最低位到最高位依次为 L Ctrl、L Shift、L Alt、L Win、R Ctrl、R Shift、R Alt、R Win；普通键以 Keyboard/Keypad usage 表示。

Nordic 固件的 `20` 和 `B0` 类都进入处理器 `20150`。配置偏移 `2C` 为 `01` 时，下列四个物理位置会被强制改写修饰位，同时将普通 usage 置零：

| 物理位置 | 浏览器布局 code | 槽位 | 强制 modifier-mask | 实际目标 |
| --- | --- | --- | --- | --- |
| 左 Win | `MetaLeft` | 12 | `04` | L Alt / L Opt |
| 左 Alt | `AltLeft` | 19 | `08` | L Win / L Cmd |
| 右 Alt | `AltRight` | 61 | `80` | R Win / R Cmd |
| 右 Ctrl | `ControlRight` | 75 | `40` | R Alt / R Opt |

因此，在 Mac 模式下把槽 12 保存为 `20 00 04`，虽然键位表可以正确读回，按键仍会输出 L Alt，而不是 A。切回 Windows 模式后，保存的 A 映射才按普通路径执行。A 槽 10 不在覆盖范围内，将 A 映射为普通 Win 动作可以正常输出 Win。

不要用显示改名、保存成功或读回一致代替实际输入验证。只把动作类别改成 `B0` 也不能绕过覆盖。宏事件 `09` 仍经过 `20150`，官方 Win 宏绑定实体左 Win 的实测未解决此问题；不应重复将同类宏当成新修复路径。

## 21 / 10 兼容编码

`21 10 usage` 进入 `201BC`，直接沿 `1EB94` 的键盘 usage 路径按下与释放，避开 `20150` 的物理位置覆盖。

`21` 原本包含周期切换逻辑。第一个参数的高半字节存入状态 `+19`；参数 `10` 使该值为 1，周期函数 `1F7D4` 在 `1F7E4` 提前返回，从而不再周期性切换按下/释放。**计数器仍递增，不能描述为停止计数。** 实体释放在 `201E6–201F0` 使用本次映射的 usage 调用 `1EB94`，然后清除共享状态 `+1A`，不依赖周期计数到时。

当前应用只在设备 Mac 模式、上述四个物理位置选择 20 类目标时进行转换，其他位置和媒体、灯光等动作类保留原编码。转换及逻辑解码见 [mac-mapping.mjs](../../src/mac-mapping.mjs)。

| 逻辑目标 | 普通编码 | Mac 四槽保存编码 |
| --- | --- | --- |
| 空白 | `20 00 00` | `21 10 00` |
| 普通键 | `20 00 xx` | `21 10 xx`，`xx` 在 `04–9B` 且属于候选库 |
| L Ctrl | `20 01 00` | `21 10 E0` |
| L Shift | `20 02 00` | `21 10 E1` |
| L Alt / L Opt | `20 04 00` | `21 10 E2` |
| L Win / L Cmd | `20 08 00` | `21 10 E3` |
| R Ctrl | `20 10 00` | `21 10 E4` |
| R Shift | `20 20 00` | `21 10 E5` |
| R Alt / R Opt | `20 40 00` | `21 10 E6` |
| R Win / R Cmd | `20 80 00` | `21 10 E7` |

单个修饰位 `1 << i` 对应 usage `E0 + i`。多个修饰位，或修饰位与非零普通 usage 的组合，无法表达为这条路径中的一个 usage，必须拒绝，不能静默取其中一个。普通键数值上限不等于开放整个 HID usage 区间；[profiles.mjs](../../src/profiles.mjs) 还会按 [keymap.mjs](../../src/keymap.mjs) 的候选库校验。

空白的静态依据是 `1EB96` 比较 usage 与 `04`，小于时经 `1EB98` 跳到 `1EC22` 返回。`00` 按下与释放都不修改键盘报告、不占数组位置；共享 `+1A=0` 也使周期处理返回。不能据此同时开放 `01–03` 错误/保留 usage。

## 实测范围

当前硬件证据来自 A80、设备 Mac 模式、Windows 主机、有线连接。各次独立修改一个槽位，再原样恢复；通过范围如下：

| 槽位 | 物理位置 | 实测编码 | 确认内容 |
| --- | --- | --- | --- |
| 10 | A，对照实验 | `21 10 E3` | 短按开始菜单、按住 A+E 打开资源管理器、松开后 E 普通输入、恢复后 A 输入 a |
| 12 | 左 Win | `21 10 E3` | 单键 Win、Win+E、松开及恢复 |
| 19 | 左 Alt | `21 10 E2` | 单键、组合、松开及恢复 |
| 61 | 右 Alt | `21 10 E6` | 单键、组合、松开及恢复 |
| 75 | 右 Ctrl | `21 10 E4` | 单键、组合、松开及恢复 |

这些记录基于用户对实际操作结果的确认，没有为本组实验新增原始 USB 报告。它们证明对应的物理位置与固定目标，不代表所有目标和位置的交叉组合均已测试。

普通 `04–9B`、空白 `00` 与新增修饰 usage `E0/E1/E5/E7` 的支持来自同一路径的静态分析，尚未有新增实机结果。多个兼容键同时按住、容量边界、macOS 主机、无线连接、冷启动后保留，以及其他设备/固件版本均未由上述逐槽实验覆盖。

RAlt 在不同主机输入布局中可能表现为 AltGraph 或伴随 Ctrl。检查这类目标时同时记录 `code`、`location`、`getModifierState('AltGraph')` 和最终释放状态，不能仅因多出 Ctrl 事件就认定映射失败。

## 五格数组与重复释放

这条路径没有把 `E0–E7` 转为报告中的独立修饰位，而是将它们放进普通键 usage 数组。`1EB94` 使用报告索引 2–6，共 **五格**。SN32 的数组描述符允许 usage `00–FF`，因此可以表示 `E0–E7`；实测 Windows 将已验证目标解释为相应修饰键。

使用兼容修饰键时，兼容修饰 usage 与普通 usage 合计应保持在五格以内。正常 20 类修饰位和空白不占这五格。四个不同兼容修饰键加一个普通键恰好占五格，这是静态容量计算，不是四键组合实测结果。

数组已满时，新 usage 经 `1EBC4 → 1EC00` 进入 NKRO 位图，字节索引为：

```text
offset = 2 + (((usage - 4) & 0xff) >> 3)
```

普通 `04–9B` 对应 offset 2–20，位于已发送的 21 字节 A5 payload 内，并匹配 SN32 的 `04–9B` 位图声明。`E0–E3` 对应 offset 29，`E4–E7` 对应 offset 30，已超出发送范围。因此必须避免先填满五格再按兼容修饰键；它不能通过此位图正常发送，且写到报告范围外的内存。第六个普通 usage 不会迁移或清空原五格，但主机合并 A6 数组与 A5 位图的实际表现未验证。宏事件 `10` 直接写相同位图，也不是可替代的修饰键路线。

不同 usage 释放时各自删除；任一 `21 10` 键清共享 `+1A` 不会清空其他已按住的数组项。相同 usage 则没有引用计数：`1EBCE–1EBDE` 会删除全部相同项，释放一个实体键可能同时解除另一个键的相同输出。

应用在四个兼容位置之间禁止重复的修饰目标。编辑草稿允许临时重复，便于交换 Cmd/Opt 等目标，但存在冲突时不能应用，写入层也再次检查。多个空白不参与此限制；重复普通目标保留固件原有行为，不保证相同输出独立释放。这些约束存在于编码和写入校验中，不依赖页面是否显示解释文字。

## 保存、显示与恢复约束

维护映射流程时保留以下行为：

1. **原始字节与显示分开。** 当前表、写前备份和导出配置保留 `21 10` 编码，不因显示为 Win/Cmd 而改回 `20`。`logicalAssignment()` 只解码逻辑目标。配置 v1 对保留槽 88 的已知表示有单独规范化，不能推广到其他槽位或当作 21 类转换。
2. **先按原始类别决定显示覆盖。** 原始 20 类在 Mac 模式的四槽显示固件强制目标；原始 21 类先解码后直接显示，不再套一次 Mac 位置交换。主机键名偏好只改变标签。
3. **写前复读设备模式。** [use-keyboard.ts](../../src/use-keyboard.ts) 将草稿对应的模式传给 `setProfile()`；[transport.mjs](../../src/transport.mjs) 在写入前重新读取 `05 / 2C`，与预期不一致或未知时停止。此检查避免读完草稿后切模式的常见情况，不构成设备端锁；写入期间不要切模式。
4. **备份当前表，核对当前表。** `08` 读取真实当前表，`07` 返回参考表，不能用 `07` 证明改键已生效。`09` 写入前保存原始 273 字节备份；完成后用 `08` 全表核对实际写入表示。超时或不一致时结果未知，停止写入，不自动重发，并保留备份以便检查恢复。
5. **重置恢复原生行为。** 重置建立原始 20 类参考表草稿，应用后恢复 Mac 模式的四槽位置覆盖。它不会自动把默认四键再次编码为 21 类，也不是恢复上次备份；原样恢复必须使用相应写前记录。
6. **同一浏览器的写入互斥。** 主应用在浏览器支持 Web Locks 时使用共享写入锁；另一页面正在写入则拒绝新的应用操作。修改前可导出当前配置，需要恢复时导入相应配置并显式应用。原始写前备份另由通信记录导出，不能直接冒充 profile v1 导入。独立实验页面已移除；历史本地备份不会被自动删除。
