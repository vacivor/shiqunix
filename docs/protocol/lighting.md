# 灯效与自定义颜色协议

本文整理当前客户端使用的灯效协议。命令值采用十六进制，配置字段和表项编号均从 0 开始，偏移采用十进制，除非另有标注。协议来源是 A80 有线连接下的官方驱动流量、用户按顺序操作的记录，以及本仓库的编码和模拟测试；网页的 L80 外观选项不代表已单独验证 L80 固件。

实现入口：[`lighting-settings.mjs`](../../src/lighting-settings.mjs)、[`lighting.mjs`](../../src/lighting.mjs)、[`transport.mjs`](../../src/transport.mjs)。这里记录配置的含义和事务顺序，不把网页动画参数当作设备协议。

## 26 字节配置

读取配置的顺序为：

1. `0x05`，偏移 `0`，长度 `1`。
2. `0x05`，偏移 `0`，长度 `26`，使用这次应答的完整 payload。

第一条短读不能代替第二条完整读回。键盘 Windows/Mac 模式另在 `0x05` 的偏移 `0x2C` 读取，不包含在这 26 字节灯效配置中。

| payload 偏移 | 当前解释 | 读取值／写入规则 |
| --- | --- | --- |
| 0 | 未确认 | 已知为 `00`，保留 |
| 1 | 灯效模式 | `01`–`08`，见下表 |
| 2 | 亮度档位 | `00`–`04`，数值越大越亮 |
| 3 | 速度档位 | `00`–`04`，反向编码：`04` 最慢、`00` 最快 |
| 4 | 未确认 | 已知为 `00`，保留 |
| 5 | 颜色选择 | `01` 全彩，`00` 单色；也观察到 `FF`，其语义尚未确认 |
| 6、7、8 | 红、绿、蓝 | 每个分量一字节；全彩时保留的 RGB 不一定参与实际效果 |
| 9 | 未确认 | 观察到 `00` 和 `08`，原值保留 |
| 10–15 | 未确认 | 已知均为 `00`，保留 |
| 16 | 写入／读回差异字段，具体语义未确认 | 配置写入用 `00`，完整读回为 `02` |
| 17–25 | 未确认 | 已知均为 `00`，保留 |

一个已知完整读回样本，模式为光谱：

```text
00 02 04 02 00 01 FF 00 00 00 00 00 00 00 00 00 02 00 00 00 00 00 00 00 00 00
```

当前客户端只在以下条件全部满足时开放配置写入：长度为 26；模式为 `01`–`08`；亮度、速度都在 `00`–`04`；颜色标志为 `00`、`01` 或 `FF`；偏移 9 为 `00` 或 `08`；其余字段符合上表的已知值。未知字段变化会停止写入，不能用上述样本整块覆盖未知设备配置。

亮度和速度在网页中的 `0 / 25 / 50 / 75 / 100` 是五档控制值，不是对物理亮度、周期或线性关系的测量：

```text
亮度编码 = 网页亮度 / 25
速度编码 = 4 - 网页速度 / 25
```

最低亮度 `00` 是否等于实体灯光全灭，不能仅凭这个数值判断。自定义全灭使用单独的颜色块。

## 八种模式与可调项

模式名称对应用户完成的八种灯效有序切换实验。早期把 `03` 标作波纹的结论已被完整实验纠正：`01` 是波纹，`03` 是呼吸。

| 模式 | 名称 | 用户观察到的行为 | 可调项 |
| --- | --- | --- | --- |
| `01` | 波纹 | 彩色图案向右移动 | 亮度、速度、全彩／单色、单色 RGB |
| `02` | 光谱 | 全键同步平滑过渡颜色 | 亮度、速度 |
| `03` | 呼吸 | 暗→亮→暗，在暗下后换色 | 亮度、速度 |
| `04` | 按键反应 | 按下的单键亮起，再逐渐熄灭 | 亮度、速度、全彩／单色、单色 RGB |
| `05` | 涟漪 | 从触发键向外扩散，每次触发使用一种颜色 | 亮度、速度、全彩／单色、单色 RGB |
| `06` | 常亮 | 全彩固定点亮，或全键统一单色 | 亮度、全彩／单色、单色 RGB |
| `07` | 百花齐放 | 每个键分别变化颜色，整体保持全彩点亮 | 亮度、速度 |
| `08` | 自定义 | 指定单色全亮／全灭 | 亮度、单色 RGB、全亮／全灭 |

应用时从刚读到的配置复制并修改支持的字段：

- 所有模式修改模式和亮度；模式 `06`、`08` 保留原速度字节。
- 模式 `02`、`03`、`07` 保留原颜色标志及 RGB。它们的残留颜色字段不能解释为实际使用单色。
- 模式 `01`、`04`、`05`、`06` 中，选择单色时写标志 `00` 和 RGB；选择全彩时写标志 `01`，保留原 RGB。
- 如果原颜色标志为 `FF`，单纯修改亮度或速度会保留它。用户明确修改颜色后才按单色／全彩写入 `00` 或 `01`。把 `FF` 解码成网页中的单色初始选择只是当前界面行为，不证明其固件含义。
- 模式 `08` 明确写单色标志 `00` 和 RGB，并要求同时指定全亮／全灭动作。

## 配置写入与核对

`setLighting()` 将模式和参数作为一次配置修改，按以下顺序串行发送，每条请求都等待对应应答：

```text
05 / offset=0 / length=1
05 / offset=0 / length=26       → 保存 before，验证已知配置范围
01
06 / offset=0 / length=26       → 修改后的 payload；payload[16] = 00
02
05 / offset=0 / length=1
05 / offset=0 / length=26       → 完整读回 after
```

`0x06` 要求完整请求回显。其后逐字节核对 26 字节配置：偏移 16 应保持写前读到的 `02`，其他字节应等于目标 payload。回显只证明收到对应应答，完整配置读回才是这里的配置核对依据。

如果非自定义模式的目标除偏移 16 外与原配置完全相同，则返回未变化，不发送配置写入。发生读回不一致或请求超时后，客户端停止后续写入，使连接失效；不自动重发。

## 自定义全亮／全灭：`0x0B`

自定义使用 **`0x0B`，即十进制 11**，发送一个 273 字节块：91 个连续三字节 RGB 项。

当前只实现全亮／全灭，不声称已经确定逐键颜色表与 83 个实体按键之间的完整映射：

- 全灭：273 字节全部为 `00`。
- 全亮：表项 `6、20、68、83、90` 保持 `00 00 00`；其余 86 项写同一颜色。
- 这 91 项是自定义灯光表项，不能直接套用普通键位表的槽位编号；86 个非零项也不等于实体键数量。

已捕获的两组全亮颜色显示，自定义块中每个非零 RGB 分量比 26 字节配置对应值少 1：

| 配置 RGB | 自定义块 RGB | 操作 |
| --- | --- | --- |
| `FF 26 2A` | `FE 25 29` | 红色全亮 |
| `00 21 FF` | `00 20 FE` | 蓝色全亮 |

当前实现将每个分量按 `max(0, 分量 - 1)` 转换。这是由上述两组样本推导的规则；任意颜色和边界值尚未逐项实机验证，不应描述为已经完整证明的色彩编码。

先完成模式 `08` 的 `0x06` 配置写入和完整读回核对，再直接发送五片 `0x0B`：

| 片 | 偏移 | 有效长度 | 覆盖范围 |
| --- | --- | --- | --- |
| 1 | 0 | 56 | 0–55 |
| 2 | 56 | 56 | 56–111 |
| 3 | 112 | 56 | 112–167 |
| 4 | 168 | 56 | 168–223 |
| 5 | 224 | 49 | 224–272 |

五片之间不插入 `0x01`／`0x02`，每次收到完整回显后立即发送下一片。末片的有效长度仍为 49，但报告余下的 7 个 payload 字节按抓包复制整个块的字节 `217–223`，参与请求校验。它们是报告填充，不是额外七个颜色数据字节。

配置亮度与自定义颜色块独立：本次抓包中，蓝色块保持不变，随后仍可修改亮度。全亮／全灭状态不在目前能够解释的 26 字节配置内；客户端读取配置时将预览开关初始化为开启，并不意味着读到了设备的全亮状态。

**自定义只核对五片回显，没有独立读取颜色块的已实现命令。** `setLighting()` 返回 `custom-echo-only`，表示配置读回已通过、颜色块逐片回显已通过；不能据此证明颜色块已经持久化、重连后仍有效，或灯光实际呈现与预期一致。写入部分分片后失败也可能已改变部分设备状态。

## 证据范围与预览近似

2026-09-09 的完整八模式实验得到 63 条请求及 63 条对应应答，八次模式写入均有后续配置读回。模式名称依据用户有序操作，不能仅由报文本身得出；按键反应的读回位于一次重新初始化之后。

2026-09-11 的参数采集包含 461 条可唯一关联应答的请求、72 次 `0x06` 配置写入。其中 70 次在下一次配置写入前取得完整读回；另外两次快速重复写入仅取得应答，不能计为完整读回验证。RGB 原色来自色板选色，不是精确的纯红／绿／蓝端点。捕获器停止方式可能丢失尾部缓冲，因此这些数量只描述已落盘并解析的数据。

同一次采集有 21 个完整自定义块，支持红色全亮、全灭、蓝色全亮及亮度独立变化的上述结论。编码测试曾逐字节复现 72 条实际配置请求，以及三次自定义操作共 15 条分片请求；模拟测试还检查同模式参数修改、保留字段、读回失败与非法参数。自动测试不等同于实体键盘视觉测试。

网页动画在 [`lighting-preview.ts`](../../src/lighting-preview.ts) 中独立实现，用于修改前预览：涟漪的实际换色顺序尚未确定，网页按触发序列模拟；百花齐放用确定性伪随机色相和平滑过渡。速度与动画周期、常亮全彩的逐键配色都不是固件算法的精确复刻。A80/L80 的键帽和字符不透光，预览仅在键帽下方缝隙显示背光。

旧实验记录中“只可写模式、参数尚未接入”及“自定义禁止写入”的状态已经被当前实现取代；自定义独立读回、逐键 LED 对应关系以及任意颜色转换的实机验证仍未完成。
