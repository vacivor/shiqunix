# 键位与动作

## 表结构与物理位置

当前键位表为 273 字节，即 91 个三字节槽位。槽位是设备矩阵编号，不是网页按键顺序，也不表示存在 91 个可编辑物理键。已识别扫描公式为 `slot = row * 7 + column`。

三字节动作在源码中作为 24 位数处理，例如 `20 00 04` 表示为 `0x200004`，`30 E2 00` 表示为 `0x30E200`。配置导出保留逐字节数组，不依赖宿主 CPU 大小端。

完整数据在 [layout-candidates.json](../../src/data/layout-candidates.json)（83 个展示按键，其中 82 个有候选槽位）和 [captured-keymap.json](../../src/data/captured-keymap.json)（91 槽参考表）。Fn 单独由固件处理，未开放映射。对普通目标的唯一值匹配是槽位定位依据之一，不能据此认定任意目标、所有位置组合都已逐项实测。

| 实体位置 | 槽位 | 参考动作 |
| --- | --- | --- |
| Esc | 0 | `20 00 29` |
| L Ctrl | 5 | `20 01 00` |
| F1 | 7 | `20 00 3A` |
| Q | 9 | `20 00 14` |
| A | 10 | `20 00 04` |
| L Win | 12 | `20 08 00` |
| End | 13 | `20 00 4D` |
| Z | 18 | `20 00 1D` |
| L Alt | 19 | `20 04 00` |
| PgDn | 41 | `20 00 4E` |
| PgUp | 48 | `20 00 4B` |
| R Alt | 61 | `20 40 00` |
| Home | 62 | `20 00 4A` |
| Right | 69 | `20 00 4F` |
| R Ctrl | 75 | `20 10 00` |

导航列由上到下是 PgUp、PgDn、Home、End。A/Q/Z/Right、L Ctrl、F1、Home 的代表性映射和恢复已由用户确认；媒体及灯光候选另有实际功能确认。未逐位置、逐目标做全排列测试。

## 普通键与修饰键

`20 modifier usage`：第二字节是修饰位掩码，第三字节是普通键 usage。

| modifier | 功能 | modifier | 功能 |
| --- | --- | --- | --- |
| `01` | L Ctrl | `10` | R Ctrl |
| `02` | L Shift | `20` | R Shift |
| `04` | L Alt / Opt | `40` | R Alt / Opt |
| `08` | L Win / Cmd | `80` | R Win / Cmd |

例：A 为 `20 00 04`，B 为 `20 00 05`，L Win 为 `20 08 00`，未分配为 `20 00 00`。双字符键帽如 `1/!` 表示同一个数字键；`!` 不是新的单键映射编码，仍由主机的 Shift 与键盘布局解释。

目前候选库开放单个普通键或单个修饰键，不提供任意 mask、修饰键加普通键的组合编辑。Mac 模式四个特殊位置的 `20` 动作会被覆盖，主应用对这些位置改用受限的 `21 10 usage`，详见 [Mac 模式](mac-mode.md)。

## 媒体、系统与背光动作

这些是从原固件 Fn 表识别的三字节动作，现可作为普通键目标。将动作写入普通键表不改变固定 Fn 表。

| 候选 | 动作 | 证据 |
| --- | --- | --- |
| Mute | `30 E2 00` | 普通键映射实测 |
| Vol − | `30 EA 00` | 普通键映射实测 |
| Vol + | `30 E9 00` | 普通键映射实测 |
| Play / Pause | `30 CD 00` | 普通键映射实测 |
| Previous | `30 B6 00` | 普通键映射实测 |

| WWW Home | `30 23 02` | 固件表与手册功能对应 |
| Ctrl+Alt+Del | `A0 AC 00` | 固件路径；不能直接称为打开任务管理器 |
| Lock Win | `A0 03 00` | 固件 Fn 表 |
| Light On / Off | `A0 AD 00` | 普通键映射实测 |

| Speed − | `A0 15 00` | 普通键映射实测 |
| Effect Cycle | `A0 10 00` | 普通键映射实测 |
| Color Cycle | `A0 16 00` | 普通键映射实测 |

`30` 类样本中的 Consumer usage 使用后两字节小端，例如 `92 01` 对应 `0192`；`A0` 类是固件内部动作，不能套用标准键盘 usage 解释。以上只开放已识别码，不由相邻数值猜测其他动作。系统分类未包含在媒体/灯光那次逐项实测确认中。

实现及英文名称：[action-targets.mjs](../../src/action-targets.mjs)。主机可能拦截、重新解释系统快捷键，网页测试收到的事件也不能证明是哪一把物理键盘发出。

## 槽位 88 与原始备份

`07` 参考表的槽位 88 为 `20 00 87`，官方 `09` 写入为 `20 00 00`。后续已验证的 `08` 读回出现 `20 00 00`，另有当前表读取的参考表示样本。因此当前实现仅接受这两种表示：

- 原始 `08` 快照及写前备份保持原字节。
- profile v1 用 `20 00 87` 保存此保留槽的参考表示。
- `encodeKeymapWrite()` 在发送前将该槽改为 `20 00 00`。
- 写后 `08` 必须与实际发送的 273 字节全部一致，不忽略保留槽差异。

不能因为 `87` 看似键盘 usage 就开放编辑槽位 88，也不能将所有未知保留值强制归零。

## 本地配置格式

JSON 格式字段：

| 字段 | 值/限制 |
| --- | --- |
| `format` | `shiqunix-keymap` |
| `version` | `1` |
| `device` | `05ac:024f` |
| `name` | 原字符串最多 60 字符，去除首尾空白后非空；保存时去除首尾空白 |
| `keymap` | 273 个 0–255 整数字节 |
| `experimental` | 布尔值；省略视为 false |

当前主应用读取为 `experimental: true`，开放已识别候选位置。历史 false 配置仅允许早期少量实测目标。校验始终检查各槽允许的完整 24 位编码；未开放槽位必须保持参考表值。`21` 仅在四个特殊位置和已识别目标上接受。

导入只生成草稿，应用才写硬件。重置生成完整参考键表草稿，不是发送未知的设备恢复出厂命令，也不重置背光。Win/Alt 与 Cmd/Opt 只是键名显示约定，不改变导出编码。

实现：[keymap.mjs](../../src/keymap.mjs)、[profiles.mjs](../../src/profiles.mjs)。
